# Практика третьего урока — «Проверка на связи»

Клиентская игра на Vite, TypeScript и Babylon.js. Практика после урока о дистанционном осмотре с приложением «Инспектор»; продолжает мастерскую из пролога. Серверной части нет.

Игрок изучает приглашение, выбирает профиль организации, подтверждает участие и настраивает разрешения. Затем составляет маршрут, осматривает мастерскую и склад, собирает снимки и действующие документы. Похожие установки, соседние секции и архивные редакции требуют сверки обозначений. Снимки отправляются в чат: Андрей сразу оценивает каждый кадр и объясняет, если объект или ракурс не подходит. Документы прикладываются там же. Затем Андрей проверяет весь комплект; верные пункты сохраняются при исправлениях. Завершение — диалог, телепортация и финальный экран.

Камера, микрофон и местоположение симулируются: разрешения браузера и реальные данные устройств не запрашиваются. Номера объектов и документы вымышлены для игрового задания.

## Запуск

```bash
npm ci
npm run dev
npm run build
npm test
```

Адрес: http://127.0.0.1:5178/git-inspection-2027-lesson-3-practice/

Стрелки — движение относительно камеры; мышь — поворот, колесо — масштаб; Enter — взаимодействие рядом. При диалоге и работе с планшетом движение отключено.

Стартовая кнопка расположена по центру размытой сцены. Во вступлении и при работе с планшетом герой достаёт его и держит обеими руками; Андрей отображается на экране. Окна и реплики располагаются выше героя. Хват перенесён из доработанного пролога: `src/scenes/characters/TabletPose.ts`, геометрия планшета — `src/scenes/workshop/createTablet.ts`.

## Структура

- `src/game/PracticeGame.ts` — загрузка, игровой цикл, управление режимами и dispose.
- `src/practice/` — сценарий, проверка комплекта, маршрут и состояние текущего прохождения.
- `src/scenes/workshop/` — помещение, объекты, ограничения перемещения, камера осмотра.
- `src/scenes/digital/PracticeWalk.ts` — анимация и перемещение персонажа.
- `src/scenes/ending/` — телепортация и финальный экран.
- `src/ui/` — планшет и диалог.
- `public/models/` — только используемые модели, зависимости и сведения о лицензиях.
- `assets/vendor/kenney-factory/` — исходный архив и манифест SHA-256; не попадают в сборку.
- `tests/state.test.ts` — проверки подготовки, ошибок комплекта и повторной сдачи.
- `tools/checks/review.html` — локальная проверка ракурсов и последовательности. Не является входом production-сборки.

## Ассеты

Новые модели: [Kenney Factory Kit 3.0](https://kenney.nl/assets/factory-kit), CC0: маленький ящик и конус. Первоначальные установки сохранены только в исходном архиве. Оригинальная текстура `Textures/colormap.png` сохранена вместе с моделями. Источники, лицензия и хеши — в `public/models/kenney-factory/SOURCE.json` и `assets/vendor/kenney-factory/manifest.json`.

Персонаж Quaternius и портреты перенесены из предыдущих частей. Сведения о персонаже — `public/models/quaternius/worker.SOURCE.json`. Окружение мастерской основано на прологе третьего урока и расширено для практики.

## Прогресс

Production проверяет ключ пролога `git-inspection-2027:lesson-3-prologue`; в dev эта проверка отключена. Прогресс практики, фотографии и чат существуют только в памяти: обновление страницы всегда возвращает к кнопке «Начать». Старые сохранения практики не читаются и новые не записываются.

GitHub и Pages для этого проекта пока не создавались. Публикация — по отдельному запросу.

Станки заменены на Bench Lathe и Pillar Drill из [Machine Shop and Factory Hall](https://3dassets.dev/packs/machine-shop-and-factory-hall), CC0. Runtime и контрольные суммы: `public/models/machine-shop/`. Исходники и сохранённые страницы лицензии: `assets/reference-models/machine-shop/`. Размещение станков задаётся в `practiceLayout.ts`: вдоль левой стены, рабочей стороной к центру.

Верстак с тисками, инструментальная панель и стеллаж с контейнерами заменяют прежние процедурные предметы. Модели из того же CC0 набора Machine Shop and Factory Hall; размещение — workshopFurniture в practiceLayout.ts. Исходные GLB, сведения о лицензии и хеши сохранены рядом с исходниками станков.

Съёмка разрешена при любом ракурсе: кадр сохраняется в галерею. Перекрытие, обрезка и отсутствие нужного объекта оцениваются Андреем после отправки в чат.

В чате кнопка «Прикрепить» открывает галерею без подписей или подборку документов. Игрок выбирает вложение, затем реплику и отправляет сообщение. Инспектор сверяет содержимое с выбранной репликой.

После съёмки фотография уменьшается и улетает в верхний левый угол; игра возвращает главное меню планшета. Снимок остаётся в галерее для отправки в чат.

Галерея содержит до пяти кадров: по одному на каждый фотозапрос. Пересъёмка заменяет прежний кадр в галерее. Чат хранит последние 12 отправок вместе с ответами Андрея; ранее отправленные фото не меняются при пересъёмке.

Изменение профиля или разрешений после подключения требует повторного «Подключиться». Камера и микрофон блокируют осмотр; личный профиль блокирует доступ к мероприятию; без местоположения можно снимать, но нельзя отправлять материалы. Сообщение Андрея отображается в чате. Исправление настроек не сбрасывает фото, документы и принятые результаты. Реальные разрешения браузера не запрашиваются.


Финал практики: принятый комплект → приглашение Андрея через планшет → самостоятельный возврат в комнату подготовки → Enter рядом с Андреем → личный диалог без планшета → телепортация только игрока и затемнение. Место прибытия пока не задано. PreparationGuide.ts управляет появлением и поворотом Андрея, guideMeeting в practiceLayout.ts — точка встречи. public/models/guide/andrey.glb и SOURCE.json скопированы из согласованного пролога (Quaternius, CC0). Кнопка отладки ведёт к приглашению, не пропускает поход к Андрею.

После прощания PracticeGame загружает ReturnOffice (отдельная Babylon Scene на общем Engine) под затемнением. Кабинет перенесён из пролога урока 1 без разрушения: геометрия и координаты в src/scenes/office/, мебель и лицензия в public/models/return-office/. Герой стоит у стеллажа в точке завершения переноса листа, без управления; это начальный кадр новой катсцены, сюжетные действия пока не заданы. Сцена освобождается при dispose/HMR.

OfficeGiftCutscene.ts продолжает возвращение: мысли над головой, поворот, обход стола, поднятие подарка двумя руками, открытие крышки и письмо Андрея. Управление заблокировано. Кнопка «Получить подарок» скачивает public/downloads/MP_inspektor.pdf (источник в SOURCE.json); загрузка инициируется только кликом пользователя. DOM/поза освобождаются при dispose.

Подарок стоит на полу рядом со столом; после открытия исчезает. В письме нет заголовка. Клик «Получить подарок» запускает скачивание, закрывает письмо и продолжает катсцену: герой садится за компьютер, думает «Это было удивительное приключение!», затем экран гаснет и появляется «Это приключение подошло к концу». Dev-кадры: previewGiftTime и (после получения) previewClosingTime.

Публичный репозиторий: https://github.com/fatco321/git-inspection-2027-lesson-3-practice. GitHub Pages: https://fatco321.github.io/git-inspection-2027-lesson-3-practice/. Публикация выполняется workflow `.github/workflows/pages.yml` при push в main.

Камера открывается отдельной кнопкой главного меню без выбора запроса. «Запросы инспектора» — чек-лист фотографий и документов со статусом приёма. Назначение фото задаёт реплика при отправке в чат. Свободная съёмка не сбрасывает уже принятые материалы; галерея хранит до пяти кадров, повторный снимок того же объекта и типа заменяет предыдущий.

Кнопка «Передать комплект на проверку» удалена. После каждой отправки проверяется полнота принятых материалов; последний верный снимок или документ автоматически запускает финальный диалог.

Общий доступ: src/progress/courseSequence.ts — одинаковый контракт шести частей. Каждая часть требует завершения всех предыдущих, без DEV-обхода; src/main.ts проверяет доступ до bootstrap.ts и загрузки сцены. Финальные экраны сохраняют только завершение своей части; игровые действия и черновики не сохраняются. Старые корректные отметки совместимы. Для iframe нужен общий origin (схема, домен и порт).

Для общей локальной проверки соберите все шесть проектов (`npm run build` в каждом), затем из проекта первого пролога запустите `node tools/checks/serve-course.mjs`. Все части доступны на http://127.0.0.1:5180/ по своим путям Vite. Отдельные порты 5173–5178 имеют раздельные хранилища. GitHub Pages одного аккаунта разделяет origin между путями репозиториев. Перенос на другой домен не переносит browser storage.
Экран загрузки: `index.html` содержит первоначальный фон и индикатор. `src/main.ts` ожидает готовности сцены через `bootstrap.ready`, затем показывает стартовый экран. При ошибке доступна кнопка «Повторить»; проверка предыдущих частей курса сохраняется.

Маршрут осмотра задаётся Андреем случайно при первом подключении и показан в чате и запросах. Следующий объект доступен для отправки после принятия всех фото и документа текущего объекта. Переподключение не меняет порядок.

После принятия материалов Андрей просит в чате подписать журнал. Журнал → Госключ → Подписать — внутриигровая имитация без внешнего сервиса и реальной электронной подписи. Только успешное подписание разрешает встречу/телепортацию и завершение; проверяются материалы и подключение.
